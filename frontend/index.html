How it works

HazardMap turns a photo or a short description into one map marker per real-world event. Classification is only a step. The harder part is deciding which reports describe the same thing. (Consult the README for more details.)

The pipeline

Report → Classification → Record → Clustering → Confidence → Map

Classification is the AI step: it turns a photo or a sentence into that standard record. How the AI works explains that part in more detail.

How two reports become one hazard

A new report joins an existing hazard when three conditions hold at once. The category matches, the distance is inside that category's clustering radius, and the hazard was last reported inside its time window. Of the hazards that qualify, it joins the nearest.

Thresholds differ by type because the hazards do. Smoke is visible from far away and often clears in hours, while a broken streetlight can stay out for days.

How confidence is calculated

Evidence accrues in log-odds, so every factor is an independent term with its own sign and weight. Each factor is multiplied together to produce the final score. The score counts distinct reporters, not submissions, so one person filing five times does not look like five different people. Confidence decays with time because a hazard nobody has reported lately may already be gone and/or resolved.

A single report is capped below certainty, no matter how confident the classification is, and nothing ever reaches 100%. Open any hazard on the map to see how the score was built.

What this system cannot do

  • Classification can be wrong. Category, severity, and access impact are all estimates/guesses.
  • Reports can be mistaken, duplicated, or deliberately false. More reports raise confidence, they do not establish truth.
  • Phone location data is imprecise, and a reporter may pin a hazard from across the street.
  • Several reports agreeing does not make a hazard real, current, or still present.
  • This is decision support. It is not a dispatching system or a system to alert authorities, and must not replace emergency services.
  • Reports are public. Anything identifying a person (PII, Personally Identifiable Information) should never be submitted.

How the AI works

When you send a report, a classifier reads your photo, your description, or both, and turns that into one standard record. Grouping reports and scoring confidence use fixed rules, not a model. (Find those rules in the How it works section.)

What the classifier does

Photo or words → Classifier → Standard record

The record always uses the same fields: hazard type, how serious it looks, whether the path is physically blocked, and whether cars and people on foot can get through. It also writes one plain sentence so similar reports read alike, and a short list of what it noticed.

The map pin is not used to guess the type. Location is used later, when HazardMap decides whether your report joins an existing marker.

Fixed list of obstructions/hazards

The classifier must pick one of the eight types already on the map, and it cannot invent a new category.

  • Fallen Tree
  • Road Obstruction
  • Flooding
  • Broken Traffic Signal
  • Road Damage
  • Fire / Smoke
  • Broken Streetlight
  • Other Hazard

When a hosted model is connected

If this copy of HazardMap has a key for a hosted model, your photo and your description are sent together to a model that can look at a picture and read writing. The model fills in the same standard record the rest of the site already uses.

It is told to describe what the report supports, not to confirm that the hazard is real. It must pick one of the eight types, or Other if none fit. It then fills in how serious the scene looks, whether the path is physically blocked, and whether cars and people on foot can get through.

It also writes one plain sentence and a short list of what it noticed. What it saw in the photo, or which phrases it used in the description. It is never allowed to reach 100% certainty from the photo or the description, only 97%.

If the hosted model cannot be reached, the built-in analyzer is used instead, and the report notes that it is using the built-in analyzer.

When no key is set (the built-in analyzer)

With no API key, nothing is sent to a hosted model (since there is none). A built-in analyzer runs on the server instead. It does not look at a new picture the way a hosted model can, but it works from familiar phrases, known demo scenes, and, sometimes, the filename of an upload.

Words: The built-in analyzer does not understand a sentence the way a hosted model does. It scans the description for familiar phrases for each type, such as “tree down,” and skips misleading ones: a cat stuck in a tree is not a fallen tree. It picks the best match. If nothing is clear enough, it leaves the type unclassified and asks for a clearer description. Other words nudge how serious it looks, where it is (road, sidewalk, intersection), and whether cars or people can get through. Very short notes get a lower certainty.

Photos: The built-in analyzer cannot look at the pixels of a new picture you upload. There are three cases:

  • The built-in demo scenes, such as a fallen tree, a flooded underpass, a dark signal, and a few others, already have a prepared reading.
  • A new upload is not seen. If the filename itself contains hazard words, that filename is treated like a short description, and certainty is kept way lower.
  • A photo with no useful filename and no description is left unclassified, with a note to add words.

Photo and words together: Each is classified on its own, then compared. If they agree on the type, certainty goes up. If they disagree, the stronger guess is kept and certainty is reduced. When the description is clear enough, its severity is preferred, because a sentence can say the road is closed when a picture cannot.

What stays the same either way (API key or no key)

Both paths produce the same kind of record and must use the same eight types of obstructions/hazards. After classification, the same non-AI rules decide whether your report joins an existing marker and how the map confidence score is built. (See How it works for those rules.)

What happens next

After classification, HazardMap asks whether this report is about a hazard already on the map. It must match the same type, be nearby, and recently reported. If so, your report joins that marker, and if not, a new marker opens.

The confidence number on each hazard is not the classifier's score. It comes from how many different people reported it, whether photos were included, how well the reports agree, and how recent they are. A single reporter is kept well below certainty, and nothing ever reaches 100%. (See How it works or the README for those rules).

What the AI will not do

  • It does not confirm that a hazard is real, current, or still there.
  • It does not call 911, dispatch anyone, or alert authorities.
  • It does not use the map pin to guess the type.
  • It does not learn from older reports. Each report is read on its own.
  • It does not reach 100% certainty. Classification confidence is capped, and the map score is capped again.

About HazardMap

HazardMap is a public-safety map built on the idea that the hard part of crowdsourced hazard reporting is not collecting reports, but it is deciding which reports describe the same real-world thing. (Consult the README for more details.)

Twelve people describing one fallen tree should produce one marker at high confidence, not twelve different pins. HazardMap classifies a photo or a sentence, groups reports that describe one event, and scores the result with an explainable confidence figure.

It is an awareness tool for streets, sidewalks, and public space. Hazards include fallen trees, flooding, dark signals, road damage, etc. smoke, and similar hazards. Please note that it is not an emergency service, and call 911 for emergencies.

The system is open source and free to use under the MIT license (as are all the other files in the repository).

HazardMap is a decision support tool, not an emergency service. Please call 911 for emergencies. High confidence does not mean verification.
